# Git
- Branch: `feature/<story-id>-<slug>` (e.g. `feature/kan-4-sdlc-pipeline`). Never commit to `main`.
- Conventional commits with the story ID: `docs(KAN-4): add requirements`.
- No force-push, no history rewrites.
- PRs go through the GitHub MCP server only, after verification passes and the human approves.
- PR body sections: Summary, Changes Made, Test Evidence, Known Limitations, Reviewer Checklist.
